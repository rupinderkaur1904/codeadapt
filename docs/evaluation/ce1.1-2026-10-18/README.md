**The false negative.** `classic_found_return.cpp` is the textbook closed-interval search
(`lo = 0`, `hi = n - 1`, `mid = (lo + hi) / 2`) that returns the first 1 it lands on. The
model uses a half-open range. "Some 1" depends on where the midpoints fall, so the two
programs return different wrong indices. A scratch comparison, compiled locally outside
the product's execution path, gave these outputs (reference / model / case):

| Test | Reference | Model | Case |
| --- | --- | --- | --- |
| `all_true` | 0 | 2 | 1 |
| `two_true` | 0 | 1 | 0 (passes) |
| `second_index` | 1 | 3 | 2 |
| `ten_answer_three` | 3 | 5 | 4 |
| `large_interior` | 123457 | 150000 | 149999 |
| `large_all_true` | 0 | 100000 | 99999 |

The method abstained rather than forcing a diagnosis, which is the intended behaviour for
an inconsistent fingerprint. But the model as written covers only one midpoint convention
of this error.
- Adding a second variant now would be fitted to a case that has already been seen.
- It would need a new held-out case written before the variant is evaluated.
- It is not applied; see the design record §7.

## Limits

- All held-out cases were written by the models' author. They are not independent.
- Their correct diagnoses show that the fingerprints recognise that author's variants. They
  say nothing about real students.
- The `returns_any_true` false negative shows that output-exact fingerprints are sensitive
  to the midpoint convention for "returns some match" errors.
