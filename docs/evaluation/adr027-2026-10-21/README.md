# ADR-027 re-run: method v1.1 vs v1.2 (2026-10-21)

The comparison required by ADR-027 §8 after the owner approved the change and policy
option P1. All data are synthetic. None of this is real-student accuracy, learning or
mastery. The v1.1 results in `../ce1.1-2026-10-18/` and `../val1a-2026-10-21/` are
untouched.

## What was run

| Set | How | v1.1 reproduces the earlier record? |
| --- | --- | --- |
| Held-out (32 cases) | Re-executed, 2 runs per case. `codeadapt-eval --compare v1.1 v1` (`heldout.md`, `heldout.json`) and `run_sets.py` (per-case consequences, `heldout-calibration.json`) | Yes, 32/32 cases identical in outcome and model to `../ce1.1-2026-10-18/heldout.md` |
| Calibration (5 cases) | As held-out (`calibration.md`, `calibration.json`) | Yes, 5/5 |
| VAL1-A (150 programs) | Replayed: the recorded observations of both runs were diagnosed with both methods (`replay_val1a.py`, `val1a.json`). Nothing was re-executed. | Yes, every run. The script stops on any difference |

All 37 held-out and calibration cases were reproducible across their 2 runs. Per-case
tables, skill observations, recommendations and feedback are in `comparison.md`
(generated by `summarise.py`).

## Results

| | v1.1 | v1.2 |
| --- | --- | --- |
| **VAL1-A** named coverage | 32/98 (33%, CI 24–42%) | **10/98 (10%, CI 6–18%)** |
| VAL1-A wrong name (strict / lenient labels) | 17/32 / 11/32 | **0/10 / 0/10 (upper 95% bound 28%)** |
| VAL1-A `non_termination_observed` | — | 30 (22 former termination diagnoses, 8 former `unmodelled`) |
| VAL1-A `incorrect` loop_termination observations | 22 | 0 |
| **Held-out** named coverage | 19/26 (73%) | **15/26 (58%)** |
| Held-out wrong name | 0/19 | 0/15 |
| Held-out `non_termination_observed` | — | 4 (all were correct v1.1 names) |
| **Calibration** | 2/5 named, 1 wrong (`clamp_with_empty_guard`) | unchanged |
| Correct programs with no failure observed | 3/3 VAL1-A, 6/6 held-out | unchanged |

**What v1.2 buys.** On VAL1-A it removes all 17 wrong names, and the
`loop_termination` failure evidence and skill-targeted recommendations built on them.

**What it costs.**

- **19 correct names are lost:** 5 on VAL1-A and 4 on held-out. Those programs now get the
  time-limit message instead of a correct hint.
- **VAL1-A named coverage falls to 10%.**
- **The one known wrong calibration diagnosis is untouched.** It does not involve a time
  limit.

**Pre-registered VAL1-A thresholds, re-evaluated under v1.2:**

| Threshold | Result |
| --- | --- |
| **T1** (wrong-name rate ≥ 10%, or Wilson upper ≥ 20%) | **Still triggered.** No name is wrong (0/10), but with only 10 names the upper bound is 28%, so the evidence cannot show the rate is low. |
| **T2** (coverage < 20%) | **Triggered** (10%). |
| T3 (B+C coverage < half of A) | Not triggered: A 4/34, B+C 6/64. |
| T4 (suite gap) | Not triggered: unchanged at 0. |

The change makes the method safer, not better covered. The labels are Claude's a-priori
labels, not human labels.

## Not changed

- Content and skill maps.
- Ledger policy 1.2, the BKT code and its parameters.
- The C6 candidate. `v2-candidate` keeps v1.1 behaviour for time limits.
